## Core change

- Optimize Cargo Node frequency handling: common single-digit numeric frequencies no longer require regex matching and repeated integer parsing.
- An invalid, oversized or malformed frequency is excluded from the current Cargo scan rather than allowing an integer overflow to abort network processing. Error reporting is deduplicated by node/value, and clears on recovery or node reclassification.
- Preserve all valid frequency behavior and routing, including numeric strings with leading zeros and legacy multi-digit values. Existing inventory operations, item metadata, network direction/rules, persistence formats, machine names and addon API signatures are unchanged.
- The Cargo change merged in [PR #422](https://github.com/wickidcow/Slimefun-Legacy/pull/422) as `9ca7840b98233e81ef7ece53ac977b524c40881a` with successful exact PR and post-merge build/addon/full-stack validation. This confirms compilation and tested behavior, **not** a measured TPS percentage.

## Release acceptance and compatibility

**Release acceptance contract:** Any new core release must demonstrate two exact-source reproducible builds with identical hashes, backwards API/baseline compatibility against the previous stable version, the canonical 45-addon bundle, real Paper 1.21.11/26.2/26.3 and experimental Purpur 26.3 full-stack tests, plus release-asset identity validation. A source-selection update to an existing release must independently preserve unrelated addon bytes and verify the published download.

**Release boundary:** Slimefun Legacy 4.1.77 publishes exactly three Java-side artifacts: the core JAR, coordinated 45-addon ZIP and official Java resource pack. Geyser handles Bedrock separately, outside Slimefun Legacy and its maintained addons. No existing release or Geyser assets are altered. Do not add Bedrock asset processing or compatibility hooks to this release.

This candidate does **not** change backpacks, cargo saves, storage schema, or installed resource packs and does not require a world migration. Back up worlds/players/Slimefun data before trying any replacement core JAR. The release workflow must preserve older releases and publish only the exact tested Java artifacts.
