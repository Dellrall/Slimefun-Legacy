# Slimefun Legacy 4.1.77 — Cargo Frequency Safety and Release Continuity

**Unreleased maintenance candidate.** Slimefun Legacy **4.1.76** remains the public core release until exact-source candidate validation, resource-pack provenance reconciliation, and release publication have succeeded.

## Core change

- Optimize Cargo Node frequency handling: common single-digit numeric frequencies no longer require regex matching and repeated integer parsing.
- An invalid, oversized or malformed frequency is excluded from the current Cargo scan rather than allowing an integer overflow to abort network processing. Error reporting is deduplicated by node/value, and clears on recovery or node reclassification.
- Preserve all valid frequency behavior and routing, including numeric strings with leading zeros and legacy multi-digit values. Existing inventory operations, item metadata, network direction/rules, persistence formats, machine names and addon API signatures are unchanged.
- The Cargo change merged in [PR #422](https://github.com/wickidcow/Slimefun-Legacy/pull/422) as `9ca7840b98233e81ef7ece53ac977b524c40881a` with successful exact PR and post-merge build/addon/full-stack validation. This confirms compilation and tested behavior, **not** a measured TPS percentage.

## Coordinated addon compatibility

The previous stable core v4.1.76 included a verified **r149** 45-addon download. This candidate retains its exact source selections until a new **4.1.77-specific** canonical build and runtime audit succeeds:

## Release gates and hold

Before publishing a new 4.1.77 core/ZIP, require the exact committed candidate to pass two clean reproducible core builds with identical checksums, backwards API/baseline compatibility against the published 4.1.76 tag `9075ea852095b28543aaa1456bc2576778cb4c4d`, the canonical 45-addon JAR bundle, real Paper 1.21.11/26.2/26.3 and experimental Purpur 26.3 full-stack tests, and the release asset identity verifier.

**Resource-pack blocker:** The live optional Bedrock ZIP currently published under v4.1.76 has SHA-256 `2f880ca6100837657fbc05daf3b383f2c3a5e5c0db58339087885b7ebebbf88e` but the reviewed repository complete-pack pin still identifies the older `60fb9fcfe19e7e5644ff7202fd83bcd2b73b9f7685f3a57797d73877153c014c` archive and only authorizes tag v4.1.76. **Do not roll back the current pack or publish a 4.1.77 Bedrock asset until its actual contents and provenance are reconciled.** This is [issue #423](https://github.com/wickidcow/Slimefun-Legacy/issues/423), not a failure of the Cargo code.

This candidate does **not** change backpacks, cargo saves, storage schema, or installed resource packs and does not require a world migration. Back up worlds/players/Slimefun data before trying any replacement core JAR. No release has been created by preparing these notes.
