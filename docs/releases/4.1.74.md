# Slimefun Legacy 4.1.74 — Energy Reliability & Safer Networks

**Official releases are available only through [GitHub Releases](https://github.com/wickidcow/Slimefun-Legacy/releases).** This document records the tested 4.1.74 source and coordinated r135 addon selection. A green pull-request or Actions artifact is not a published release. The previous stable [4.1.73](https://github.com/wickidcow/Slimefun-Legacy/releases/tag/v4.1.73) and its r134 bundle remain available for backup and rollback.

## Core: energy-network presentation reliability

- [EnergyNet PR #377](https://github.com/wickidcow/Slimefun-Legacy/pull/377) corrected a timer-phase bug that could prevent powered connector/redstone presentation state from self-healing when a regulator ticked at a fixed cadence. Per-network deadlines now force periodic revalidation without requiring an exact modulo world tick.
- Dirty topology and changed power states still refresh immediately. This **does not** change actual generation, consumption, charge storage, power routing, item/research IDs, recipes, or stored-world serialization.
- Previous-stable required regression baseline: the *exact published* 4.1.73 source commit `6c3cd1e561f1231701d6de3256a8e808243c1370`. The historical 4.1.15 saved-item floor remains advisory.

## Server-owner upgrade checklist

1. **Back up before changing anything:** stop your server and copy worlds, `plugins/Slimefun` data, add-on folders, databases, player inventories, config files and the complete previous plugin set. Retain the working **4.1.73/r134** ZIP and individual JARs in a rollback directory.
2. Download only the **official published** `Slimefun-Legacy4.1.74.jar` and matching `SF_Addons_1.21.11-26.3.zip` after the controlled 4.1.74 release is available. Do not mix an r135 ZIP with an older core just because the filenames look familiar.
3. Remove/replace old Slimefun core, Networks and FluffyMachines JARs in the server `plugins` directory—never load two versions of the same plugin. Install only the other addons you actually use; do not install all 45 unnecessarily.
4. Confirm **Paper/Purpur 1.21.11+** compatibility and the matching Java runtime: Minecraft 1.21.11 uses Java 21; 26.2/26.3 need Java 25. The JARs target Java 21 bytecode for the supported baseline.
5. Start normally (**never `/reload`**). Inspect console startup for `NoClassDefFoundError`, `NoSuchMethodError`, and failed plugin enables. Run `/sf versions`, `/sf doctor status`, `/sf doctor compatibility`, and `/sf doctor runtime`.
6. Check existing inventories, old custom/PDC items, backpacks, Quantum Storage, Fluffy Barrels and Networks item-grid totals. Verify quantities after a clean shutdown/restart before admitting production players.
7. For performance comparisons, sample `/sf tick top` and spark on a comparable world copy with matched loaded chunks, player population and machine count. Avoid inferring better TPS from a source optimization alone.

**Rollback:** shut down, restore the complete pre-upgrade backup (not just the previous core JAR), reinstall the matching **4.1.73/r134** set, then start cleanly. Never reopen a newer-written live database under older plugin code without restoring its known-good snapshot.

## Adoption metrics and support

Slimefun Legacy uses bStats plugin ID **32960**, unchanged across 4.1.71–4.1.74 development. The public dashboard reports aggregated participating servers—not uniquely identified installs. Counts can vary with online uptime, telemetry disabled by operators, blocked HTTP submissions and reporting windows; a lower value alone does **not** prove a specific number of uninstallations. If a plugin fails to load or stops functioning, collect your exact Minecraft/Paper/Java version, Slimefun `/sf versions` result, full startup exception and steps to reproduce, then open a [GitHub issue](https://github.com/wickidcow/Slimefun-Legacy/issues) with identifying/private data redacted.
