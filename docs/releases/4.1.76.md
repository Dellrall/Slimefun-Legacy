# Slimefun Legacy 4.1.76 — 26.3 Compatibility and Backpack Reliability

**Unreleased candidate — publication held.** The maintainer must explicitly authorize publication after the Networks Expansion repair work is ready. Merged changes and successful CI runs do not authorize a release.

Slimefun Legacy 4.1.76 fixes backpack request ownership and Folia task cleanup, and coordinates the JustEnoughGuide startup dependency fix with the 45-addon **r142** bundle. It carries forward the atomic save repair released in 4.1.75 and uses that exact published source as the release-blocking compatibility baseline.

## Backpack requests across reconnects

Each backpack open request now has its own temporary in-memory token. A delayed profile or backpack-load callback must still own that request before it can read player state, open an inventory or release a reservation. This prevents a callback from an earlier connection from clearing a newer pending or active session, including when both requests refer to the same backpack.

The initial profile continuation now reaches the player's owner executor before reading player or inventory state. Cleanup also preserves a reservation while its accepted save is pending; only that save's matching completion can release it. Existing public entry points, backpack UUIDs, legacy keys and stored data formats remain intact. No data migration is required.

The regressions exercise actual compiled listener continuations with controlled callback delivery. They cover same-key and different-key successors, stale profile/load completion, current-request failures, accepted-save holds and owner dispatch. Removing the early ownership guards makes the stale-player controls fail. These checks do not claim a connected-client reconnect or a transaction across a player's ordinary inventory and another plugin's storage.

## Folia 26.3 entity-retirement cleanup

The scheduler preserves caller cleanup when Folia rejects a task because its entity has already retired. Immediate, delayed and zero-delay submissions previously returned cancelled handles without running cleanup, leaving waiting callers unresolved. The candidate invokes the existing guarded cleanup exactly once, while normal accepted work and explicit cancellation retain their behavior.

All nine focused Java regression cases pass after the fix; the unchanged code failed the three rejected-submission cases. A native Folia 26.3 build 3 (ALPHA) fixture reproduces those three failures and passes all 27 assertions with the fix. The Purpur 26.3 comparison passes all 26 assertions for its existing Bukkit scheduler behavior. Both native test servers stopped normally with no tracked tasks left. These are scoped lifecycle checks, not full addon or cross-region gameplay certification.

## JustEnoughGuide 2.1.73

JustEnoughGuide packages its existing Pinyin search libraries and dictionaries in the addon JAR. Guide startup therefore no longer needs to acquire these libraries from an external repository. This resolves the startup failure recorded in [the guide dependency follow-up](https://github.com/wickidcow/Slimefun-Legacy/issues/378#issuecomment-6206736869).

The update preserves the existing Pinyin dependency versions, dictionary contents, public Pinyin API names, guide ownership, item and recipe identities, and saved data. Normal Pinyin search remains available with the bundled libraries.
