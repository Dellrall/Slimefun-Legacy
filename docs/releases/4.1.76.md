## Backpack requests across reconnects

Each backpack open request now has its own temporary in-memory token. A delayed profile or backpack-load callback must still own that request before it can read player state, open an inventory or release a reservation. This prevents a callback from an earlier connection from clearing a newer pending or active session, including when both requests refer to the same backpack.

The initial profile continuation now reaches the player's owner executor before reading player or inventory state. Cleanup also preserves a reservation while its accepted save is pending; only that save's matching completion can release it. Existing public entry points, backpack UUIDs, legacy keys and stored data formats remain intact. No data migration is required.

The regressions exercise actual compiled listener continuations with controlled callback delivery. They cover same-key and different-key successors, stale profile/load completion, current-request failures, accepted-save holds and owner dispatch. Removing the early ownership guards makes the stale-player controls fail. These checks do not claim a connected-client reconnect or a transaction across a player's ordinary inventory and another plugin's storage.

## Folia 26.3 entity-retirement cleanup

The scheduler preserves caller cleanup when Folia rejects a task because its entity has already retired. Immediate, delayed and zero-delay submissions previously returned cancelled handles without running cleanup, leaving waiting callers unresolved. The candidate invokes the existing guarded cleanup exactly once, while normal accepted work and explicit cancellation retain their behavior.

All nine focused Java regression cases pass after the fix; the unchanged code failed the three rejected-submission cases. A native Folia 26.3 build 3 (ALPHA) fixture reproduces those three failures and passes all 27 assertions with the fix. The Purpur 26.3 comparison passes all 26 assertions for its existing Bukkit scheduler behavior. Both native test servers stopped normally with no tracked tasks left. These are scoped lifecycle checks, not full addon or cross-region gameplay certification.

## Optional Bedrock resource pack — Geyser required

This candidate adds the [complete experimental Bedrock resource bundle](../../compatibility/bedrock/SFL_GEYSER_RP_experimental_v1.0.3_complete.zip), **`SFL_GEYSER_RP_experimental_v1.0.3_complete.zip`**, as an optional download for Bedrock players. **Geyser must be installed and configured, and both main resource packs and all 23 matching JSON mappings must be installed together for this integration to work.**

The complete ZIP includes the base files needed for a fresh installation, the updated Slimefun and Albion ValhallaMMO main packs at component version 1.0.1, and the original 1,453 skull hashes plus 90 additions, for **1,543 unique skulls**. It retains all **507 Albion item definitions**. The **ValhallaMMO stat-icon font pack is optional** and stored under `optional/`; it is not installed by default. All 27 supplied component files are copied unchanged, including the geometry, armor and material changes supplied by the 1.0.3 overlay. The new `INSTALL.md` explains the complete installation. No earlier ZIP is required; the separate public overlay alone assumes an existing base installation.

After a normal Geyser shutdown and backup, copy the two main `.mcpack` files from `packs/` to the active Geyser instance's `packs/` directory and all 23 JSON files from `custom_mappings/` to its matching directory. The main packs retain their previous UUIDs: move the older versions outside the active pack directory after backing them up, keeping only one version of each. Preserve unrelated files and configuration. Copy the optional stat-icon pack only if wanted, enable `gameplay.enable-custom-content`, and restart normally. For Geyser-Spigot, the destination is `plugins/Geyser-Spigot/`; proxy and standalone deployments must use the instance actually running Geyser. Both skull files remain JSON in `custom_mappings/`. See the [installation and upgrade instructions](../bedrock-resource-pack.md).

The download is separate from the Java resource pack and addon JAR bundle. It includes no Geyser JAR or configuration and does not install the corresponding gameplay plugins. The exact complete ZIP passed isolated **Geyser Standalone 2.12.0 build 1268** loader checks both with the two required packs and with the optional stat-icon pack enabled separately. Both runs registered **1,543 custom skulls and blocks**, generated all 1,543 skull textures, preserved the 28 input files and shut down normally. The **107 texture-size deprecation warnings** still require a future mapping migration. No Bedrock client or live Java backend connected; client rendering, item interactions and embedded Geyser-Spigot/Folia behavior remain untested. The bundle remains experimental.

The complete ZIP is stored with the source and pinned at **2,390,264 bytes**, SHA-256 `60fb9fcfe19e7e5644ff7202fd83bcd2b73b9f7685f3a57797d73877153c014c`. Release acquisition uses those exact committed bytes, so replacement of an older public asset cannot change this candidate's source download.
