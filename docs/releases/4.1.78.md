# Slimefun Legacy 4.1.78 — Dependency Reliability and Inventory Safety

**Java-only maintenance release.** Version 4.1.77 is the previous published core baseline. GitHub Releases, not a PR or draft note, is authoritative for 4.1.78 publication.

## Core maintenance since 4.1.77

- **Fail-closed physical inventory capacity checks** ([PR #441](https://github.com/wickidcow/Slimefun-Legacy/pull/441)). `ItemStackService.fits` and `fitAll` validate each explicitly requested physical slot against the inventory size before forwarding to Dough or the virtual-item path. Invalid indices return `false` instead of causing `ArrayIndexOutOfBoundsException`; valid selections and unqualified all-slot checks retain their prior behavior. Focused MockBukkit regressions cover 18-slot and 54-slot inventories, invalid/mixed indices and no mutation. This protects callers using Slimefun's service; direct addon calls into Dough require their own checks.
- **Dependency repository isolation** ([PR #440](https://github.com/wickidcow/Slimefun-Legacy/pull/440)). Scope dynamic Paper API metadata resolution to PaperMC, and existing pinned mcMMO 2.1.225 and Orebfuscator API 5.3.0 resolution to CodeMC. Avoid unrelated PlaceholderAPI Maven HTTP 522 failures while preserving coordinates, versions and Java code. Fail closed if the authoritative repository itself is unavailable.
- No machine recipe, item identifier, persistent data format, Cargo routing, energy behavior, or addon-facing API change is intended in these fixes.

## Platforms and coordinated addons

- Primary validation: Paper 1.21.11, 26.2 and 26.3, with Purpur 1.21.11 and 26.2. Purpur 26.3 remains an experimental runtime target.
- Leaf 26.2 and Folia 26.2/experimental 26.3 use separate real-server restart/readiness checks. Folia multi-region Cargo/energy transfer and all addon gameplay are **not** certified by successful core startup.
- Retain the coordinated **r150** 45-addon source selection from the published 4.1.77 maintenance ZIP. This includes Networks 1.0.61, SlimeHUD 2.0.7, MagicExpansion 1.1.18 and InfinityExpansion2 2.0.15; the remaining 41 source pins are unchanged. A new release must still produce and validate a bundle from the exact new core commit.

## Release acceptance

Require two identical clean core JAR builds, preserved Java 21 bytecode output using the Java 25 builder, API/baseline checks against published **v4.1.77** commit `a8b62908e6fb8fd949f585faa7de30e863c6deaa`, canonical 45-addon bundle source identity, Paper/Purpur full-stack restarts, Folia/Leaf smoke checks, and native storage regressions from the exact release source. Older CI results are not substitutes.

Only the core Java JAR, canonical addon ZIP, and optional official **Java** resource pack are in this release scope. Bedrock/Geyser is administered separately and must not be developed, packaged, copied, validated or published by Slimefun Legacy or its addons. Existing public releases and their assets remain untouched. No player/item/world data migration is required by these two repairs; back up server data before installing any core update.
